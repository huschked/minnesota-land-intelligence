# Reproducibility and recovery (ML-120)

## Baseline and boundaries

The initial local Git baseline contains source, configuration examples, docs,
planning, scripts, sanitized test fixtures, and empty data-directory placeholders.
It excludes the virtual environments, raw county downloads, imported listings,
processed results, original correspondence, secrets, and private key files.
Documentation contains reviewed factual summaries and public parcel examples, not
the original county dataset or email files. ML-120 initially created a local-only
baseline. A separately authorized follow-up on 2026-10-14 connects `origin` to
[huschked/minnesota-land-intelligence](https://github.com/huschked/minnesota-land-intelligence),
verified private before the first push. This backs up committed code and docs,
not ignored county data, and does not deploy the application. **County data still
requires its own private backup.**

Find the exact baseline with `git log --max-parents=0 --oneline`. Future runs record
the current revision, rather than embedding a circular self-reference in this file.
Do not switch or restore revisions over uncommitted work; preserve it first or
recover into a separate checkout.

## Clean environment

The observed resolution in [constraints-dev.txt](../constraints-dev.txt) targets
Windows x64, CPython 3.12.14. The project still declares Python >=3.11. ML-118 adds
CI coverage for Windows/Linux with Python 3.11/3.12; the actual run outcome is
recorded in [testing](testing.md), not implied for every Python >=3.11 release.
From the project root in PowerShell, with a standard Python installation:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]" -c constraints-dev.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests scripts
.\.venv\Scripts\python.exe scripts/render_kanban.py --check
```

Create `.venv` only if it does not already exist. Installation requires an allowed
package index or a separately retained wheelhouse. Constraints pin the observed
runtime/test/lint resolution, including transitive packages; they are **not** a
hash-locked, fully offline, cross-platform build. Build isolation still resolves
the `hatchling` backend declared in `pyproject.toml` and its own dependencies.
Do not claim byte-identical packaging from these constraints. Future run manifests
capture installed distribution versions, including additional installed packages.

This workstation's existing project venv has no pip. The bundled Python can manage
a separate venv using `python -m pip --python <venv-python> install ...`. This is a
local workstation fallback, not a required hardcoded path in project code.

If Windows denies access to pytest's default temporary directory, use a **new,
unused** project-local name, for example:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=.test-tmp-recovery-001
```

Never point `--basetemp` at a data/source/backup directory: pytest may clear it.
ML-118 makes bare `pytest` offline by default; `pytest -m integration` explicitly
selects live tests instead. See [testing](testing.md) for the selection regression
checks and the network guard. Test dependencies may still require network access
to install; offline here describes test execution, not package installation.
The two optional PDF comparison scripts additionally need `pypdf`; it is not a
core pipeline dependency or part of the development resolution.

## What new runs record

- GIS raw `manifest.json`: actual request settings, transport timeout/retries when
  available, code/runtime identity, hashes for metadata and raw pages.
- Parcel `execution.json` inside its raw run directory: minimum acreage, adapter,
  raw input hashes, and the four derived export hashes.
- Delinquency processed `manifest.json`: code/runtime, minimum acreage, preserved
  source/mapping/supporting-document hashes, exact parcel input snapshot hashes,
  and all exported result hashes.
- Review `summary.json`: code/runtime, minimum acreage, exact join/listing/GIS and
  optional comparison inputs, plus the seven review CSV hashes.

Manifest/summary self-hashes are excluded. Missing declared artifacts fail rather
than being silently skipped. Missing Git leaves revision unknown; dirty state is
separate from revision. The actual package source tree is also hashed, which helps
identify uncommitted code but does not make it recoverable without saving it.
Run with a clean committed tree for recoverability; don't edit code or dependencies
during execution. Historical snapshots retain their original unknown code identity.
No existing county snapshot is regenerated by this baseline task.

These hashes detect changed bytes when compared against trusted retained manifests;
they are not signatures, transactional publication guarantees, or proof of the
semantic correctness/currentness of a government record. For a recorded artifact,
compare its listed digest with:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '<recorded artifact path>'
```

## Data and recovery

Git recovery alone will not restore results. Separately back up `data/raw/`,
`data/import/`, and `data/processed/` together, retaining source files, mappings,
supporting correspondence, manifests, and outputs. Keep that backup private and
separate from the working copy. Verify copied file hashes before relying on it.
Do not add ignored county data or correspondence to Git to compensate for a
missing backup.

For recovery, use a separate checkout of the recorded clean revision, create a
fresh environment using the retained constraints, and restore the matching data
backup without overwriting existing work. Current join manifests store absolute
paths; if the workspace moved, preserve the restored originals and make a new,
documented replay configuration rather than silently rewriting lineage. Explicit
portable replay is ML-123, not a capability supplied here.

Confirm counts, relevant tests, mapping/source hashes, and output hashes against
the retained record. If the run was dirty or its revision unknown, the commit
alone cannot recover it. If data or dependency wheels were not backed up, do not
claim complete offline recovery; a new county retrieval is a new dated snapshot,
not a replacement for historical evidence.

The private code repository can be cloned to a new, empty destination with
`git clone https://github.com/huschked/minnesota-land-intelligence.git` after
authenticating with an authorized GitHub account. Do not put credentials in the
URL or source files. Preserve the private visibility; adding collaborators or
publishing the repository requires a separate decision.

## Verification record

2026-10-14: existing environment offline suite passed 66 tests (one live test
deselected), including new configuration/artifact hashing, missing-artifact,
clean/dirty/unborn/unavailable Git, unrelated repository, and mocked parcel
end-to-end provenance checks. Existing join and review fixture tests also validate
the new manifest fields. Ruff passed for `src`, `tests`, and `scripts`.
Default Windows pytest temp/cache locations had permission errors; a new local
test directory and disabled cache resolved them.

A separate `.venv-ml120` was created without reusing site-packages. Installation
of `.[dev]` constrained by `constraints-dev.txt` succeeded via the bundled pip.
That fresh environment passed the same 66 offline tests (one live test deselected),
Ruff, `pip check`, and `python -m mn_land.cli --help`. No live county API test was
run. The validation venv and local test artifacts remain ignored and can be
discarded independently; the active `.venv` and historical data were not replaced.

Baseline audit: reviewed the candidate file inventory and sanitized fixtures;
common private-key/token/password patterns had no matches in the candidate code,
docs, scripts, and fixtures. This is a bounded review, not a credential-scanner
certification. `git check-ignore` confirmed data, environments, local settings,
secret directories, and original email files are excluded while `.env.example`,
sanitized fixture CSVs, and data placeholders remain eligible for tracking.
